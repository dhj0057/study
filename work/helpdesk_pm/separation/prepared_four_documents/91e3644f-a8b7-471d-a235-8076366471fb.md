# AI Smart Help Desk · 처음 30분 시작 안내

처음에는 프로젝트를 열고, 본인 작업 한 개를 찾고, 도움을 요청하는 방법까지 익히면 됩니다. 코딩이나 Linear 사용 경험이 없어도 이 순서대로 진행할 수 있습니다. 팀장 **도형준**이 A 역할과 전체 통합을 맡고, B\~E는 팀원과 상의해 배정합니다.

**우리 프로젝트:** [AI Smart Help Desk · 인공지능플랫폼실습 팀 프로젝트](<https://linear.app/dhj00570-helpdesk/project/3903fba1-33a6-4627-a25e-4481d65f7d35>)

**일정:** 외부 마감 2026년 12월 2일 / 팀 내부 최종 제출 12월 1일 21:00 / 기능 동결 11월 24일. 외부 제출 시각과 발표일은 공지 확인 기준입니다.

이 시작 과정에서는 **유료 결제나 API 키 입력을 진행하지 않습니다.** 계정에서 플러그인을 사용할 수 없다면 아래의 ‘본문 복사 방법’으로 참여하면 됩니다. 이 문서는 설치와 연결을 안내하며, 팀원 계정의 설치가 이미 완료되었다는 뜻은 아닙니다.

이후 B·C의 실제 모델 연결에 필요한 API 키는 도형준과 발급·관리 방식을 정합니다. 키 값은 채팅·Linear 댓글·캡처로 공유하지 않습니다.

## 0\~5분 · Linear에 가입하고 우리 프로젝트만 열기

1. 도형준에게 받은 **팀 초대 링크**를 엽니다. 초대를 받지 않았다면 먼저 초대를 요청합니다.
2. 본인이 사용할 계정으로 가입하거나 로그인하고 초대를 수락합니다. 계정이 있다는 것과 팀 프로젝트에 접근할 수 있다는 것은 별개입니다.
3. 위의 우리 프로젝트 링크를 엽니다. 화면의 프로젝트 이름이 **AI Smart Help Desk · 인공지능플랫폼실습 팀 프로젝트**인지 확인합니다.
4. 프로젝트 설명과 작업 목록을 읽습니다. 지금은 상태·담당자·마감일을 바꾸지 않습니다.

Linear의 이슈(issue)는 ‘해야 할 일 한 개’입니다. B\~E의 큰 역할 아래에 **T03, T04 같은 개별 작업**이 있습니다. 처음에는 큰 역할 전체를 끝내려 하지 않고, 배정받은 개별 작업 한 개를 진행합니다. 다른 프로젝트의 작업은 건드리지 않습니다.

프로젝트가 보이지 않으면 새 프로젝트를 만들지 말고 도형준에게 ‘가입한 계정 이름’과 ‘우리 프로젝트가 열리지 않는 상황’을 알려주세요.

## 5\~12분 · ChatGPT 또는 Codex에 Linear 연결하기

본인이 사용 가능한 ChatGPT 또는 Codex 화면에서 진행합니다. 공식 기본 절차는 **Plugins → 검색 → 상세 → 설치 → 연결**입니다. [공식 Plugins 안내](<https://learn.chatgpt.com/docs/plugins>)

1. **Plugins** 탭을 엽니다.
2. 검색창에서 **Linear**를 찾습니다.
3. Linear 플러그인의 상세 화면을 열고 설치 버튼을 선택합니다. 공식 안내에서는 더하기(+) 버튼으로 표시됩니다.
4. 연결 안내가 나오면 **본인의 Linear 계정**으로 로그인합니다. 방금 초대를 수락한 계정과 같은지 확인합니다.
5. 요청되는 연결 권한과 대상 계정을 확인하고 연결을 마칩니다. 설치할 때 연결 안내가 없으면 처음 사용할 때 나타날 수 있습니다.
6. 새 채팅을 열고 아래 ‘복사할 질문 1’을 보냅니다. 설치한 플러그인의 기능은 새 채팅에서 사용할 수 있습니다. [설치·연결 공식 절차](<https://learn.chatgpt.com/docs/plugins>)

설치 메뉴가 없거나 계정에서 사용이 제한되면 결제나 별도 API 키 발급으로 해결하지 않습니다. 화면에 나온 문구를 기록하고 아래 본문 복사 방법으로 진행합니다. 제공되는 기능은 계정·작업 공간에 따라 다를 수 있습니다.

**Linear 플러그인으로 할 수 있는 일:** 접근 권한이 있는 이슈를 읽고, 요청한 범위에서 설명·상태·기록 등을 관리하는 일입니다. **실제 코드 수정**을 하려면 별도로 프로젝트 코드가 있는 로컬 폴더나 공유 저장소가 작업 환경에 연결되어 있어야 합니다. Linear 연결만으로 팀 코드 폴더가 자동으로 생기지는 않습니다.

### 코드 작업을 맡은 뒤 · GitHub 추가 연결

AI에게 GitHub 이슈·PR·저장소 조회를 맡길 때 선택적으로 연결합니다. 팀 저장소를 받은 로컬 폴더가 준비되어 있다면 GitHub 플러그인 연결 없이도 코드 작업을 시작할 수 있습니다.

도형준이 실제 팀 저장소 주소와 초대를 공유한 뒤 진행합니다.

1. 본인 GitHub 계정으로 저장소 초대를 수락하고, 브라우저에서 팀 저장소가 열리는지 확인합니다.
2. AI 도구의 **Plugins**에서 **GitHub**를 검색해 설치하고 본인 GitHub 계정으로 연결합니다.
3. 연결 대상에 팀 저장소가 포함되어 있는지 확인합니다. 권한이 없으면 도형준에게 저장소 접근을 요청합니다.
4. AI에게 “팀 저장소 \[실제 주소\]에 접근 가능한지 읽기만 확인하고, 현재 작업 폴더가 그 저장소인지 확인해줘”라고 요청합니다.
5. 로컬에서 코드를 수정·실행할 도구라면 팀 저장소를 내려받은 폴더를 작업 공간으로 엽니다. 저장소 연결과 로컬 폴더 연결은 각각 확인합니다.

GitHub 연결만으로 로컬 실행 환경이 준비되는 것은 아닙니다. 폴더가 없거나 실행 방법이 불명확하면 README와 설치 순서를 도형준에게 확인합니다. 지금은 임의의 저장소나 다른 수업 폴더로 대신하지 않습니다. 설치 방식은 Linear와 같은 [공식 Plugins 절차](<https://learn.chatgpt.com/docs/plugins>)를 따릅니다.

## 12\~16분 · 읽기만 되는지 먼저 확인하기

새 채팅에 다음 내용을 그대로 복사합니다. 첫 테스트에서는 내용을 바꾸지 않습니다.

### 복사할 질문 1 · 내 계정과 우리 프로젝트 읽기 확인

```text
Linear 플러그인으로 읽기 확인만 해줘.

대상 프로젝트:
https://linear.app/dhj00570-helpdesk/project/3903fba1-33a6-4627-a25e-4481d65f7d35

1. 현재 연결된 내 Linear 계정 이름을 확인해줘.
2. 위 프로젝트에 접근할 수 있는지 확인하고 프로젝트 이름·팀장·소속 팀을 알려줘. 팀장은 도형준, 소속 팀 코드는 NONONO인지 확인해줘.
3. 이 프로젝트 안에서 내 계정에 배정된 이슈만 알려줘. 없으면 미배정이라고 알려줘.

계정이나 접근 여부를 확인할 수 없으면 추정하지 말고 멈춰서 필요한 내용을 물어봐.
다른 프로젝트를 읽거나 변경하지 마.
프로젝트·이슈·문서·댓글·담당자·상태·마감일·코드를 수정하지 마.
```

답변의 계정 이름이 본인과 맞고 우리 프로젝트가 확인되면 읽기 테스트가 된 것입니다. 이슈가 없다고 나오면 역할 배정 전일 수 있으므로 다음 단계에서 도형준에게 확인합니다. 다른 계정이 나오면 그 상태로 작업하지 말고 본인 계정 연결을 다시 확인합니다.

## 16\~20분 · 도형준에게 이름·희망 역할·가능 시간 알려주기

아래 내용을 팀에서 정한 대화 채널에 **본인이 직접** 보냅니다. AI에게 다른 팀원에게 연락하도록 맡길 필요는 없습니다.

```text
이름: [실명]
Linear에 표시되는 내 계정 이름: [이름]
프로젝트 열기: [가능 / 안 됨]
AI의 Linear 읽기 테스트: [성공 / 본문 복사로 진행 / 막힌 내용]
희망 역할: [B / C / D / E, 가능하면 1·2순위]
주당 가능한 시간: [예: 4시간]
작업 가능한 시간대: [요일과 시간]
처음에 도움이 필요한 부분: [없음 또는 한 문장]
```

| 역할 | 맡을 일 | 처음 해볼 일 |
| -- | -- | -- |
| B · 문의 분류 | Jev 사용 가능 여부와 문의 분야·긴급도 판단 | 가상 문의 1건의 분류 결과 확인 |
| C · FAQ와 답변 | 시연용 FAQ와 Gemini 안내 답변 | FAQ 초안과 답변 근거 정리 |
| D · 화면과 배포 | 사용자·관리자 화면, 무료 데모 실행 | 고정 예시를 보여주는 기본 화면 |
| E · 검증과 발표 | 예상 정답, 오류 재현, 발표 자료 | 가상 문의와 기대 결과 작성 |

도형준이 역할과 개별 작업을 배정한 뒤 시작합니다. 배정 전에는 역할 설명을 읽고 궁금한 점을 정리하면 됩니다. 다른 사람의 이슈를 본인에게 임의로 가져오지 않습니다.

## 20\~30분 · 배정된 이슈 한 개로 첫 작업 시작하기

1. 왼쪽 My issues(내 작업)를 열거나, 우리 프로젝트의 이슈 목록에서 **Assignee(담당자) → 본인**으로 좁힙니다. 그중 **T번호가 붙은 개별 이슈 한 개**를 엽니다. 목록이 비어 있으면 도형준에게 배정을 요청합니다.
2. 이슈의 **목표·마감·선행 작업·완료 조건**을 읽습니다. 선행 작업은 ‘이 일이 끝나야 내 작업을 마칠 수 있는 앞선 일’입니다.
3. 선행 작업이 막혀 있으면 도형준에게 알립니다. 지금 준비할 수 있는 자료나 고정 예시가 있는지도 확인합니다.
4. 시작할 수 있으면 해당 이슈만 In Progress(진행 중)로 옮깁니다. AI가 생성한 글만 보고 완료로 바꾸지 않습니다.
5. 이슈 링크를 복사해 아래 질문의 대괄호 부분을 채웁니다.

### 복사할 질문 2 · 내 이슈 한 개에 대한 작업 도움

```text
나는 AI Smart Help Desk 프로젝트에서 [B/C/D/E] 역할을 맡았어.
내게 배정된 개별 이슈는 [여기에 이슈 링크]야.

이 프로젝트와 내 이슈 한 개만 대상으로 도와줘.
먼저 목표·선행 작업·마감·완료 조건을 읽고, 내가 지금 할 일을 3단계 이내로 정리해줘.
자료가 충분하면 내 역할의 작은 산출물부터 함께 만들어줘.
모르는 조건이나 필요한 자료가 없으면 추정하지 말고 멈춰서 물어봐.

코드 작업이면 프로젝트 코드 폴더나 공유 저장소가 현재 작업 환경에 연결되어 있는지 먼저 확인해줘.
없으면 폴더·저장소 연결에 무엇이 필요한지 물어보고, 코드를 이미 수정했다고 말하지 마.
코드 수정은 내가 연결한 팀 프로젝트 코드와 이 이슈 범위에서만 해줘.
공통 데이터 형식이나 다른 담당자의 모듈을 임의로 바꾸지 마.

실제로 확인한 결과와 아직 확인하지 않은 부분을 구분해줘.
다른 프로젝트·다른 사람의 이슈·담당자·마감일은 변경하지 마.
검증과 다른 팀원의 확인 전에는 Done으로 바꾸지 마.
```

첫 결과는 작아도 괜찮습니다. FAQ 초안, 가상 문의와 예상 결과, 화면 캡처, 실제 호출 기록, 코드 변경과 실행 결과 중 **본인 이슈에 맞는 한 가지**를 남깁니다. 작업 전체가 끝나지 않았다면 진행 내용을 기록하고 다음 할 일을 적습니다.

## 결과가 준비되면 · 증거를 붙이고 검토 요청하기

AI 답변은 작업을 돕는 초안입니다. 본인이 실제 파일을 열거나 화면을 실행해 이슈의 완료 조건을 확인합니다. 실행하지 않은 결과를 성공했다고 적지 않습니다.

### 복사할 질문 3 · 검토 요청 댓글 초안 만들기

```text
대상은 AI Smart Help Desk의 내 이슈 [이슈 링크] 한 개야.
내가 한 일: [한두 문장]
실제로 확인한 증거: [실행 결과·가상 입력·화면 캡처·파일 또는 PR 링크]
아직 확인하지 못한 점: [없음 또는 내용]

이슈의 완료 조건과 내 증거를 비교해줘.
부족한 조건이 있으면 구체적으로 알려주고, 모르는 내용은 추정하지 말고 질문해줘.
조건을 충족했다면 검토자에게 보여줄 짧은 댓글 초안을 작성해줘.
실행하지 않은 테스트를 통과했다고 쓰지 마.
댓글 게시와 상태 변경은 하지 말고 초안만 보여줘.
다른 프로젝트나 다른 이슈는 변경하지 마.
검증과 다른 팀원의 확인 전에는 Done으로 바꾸지 마.
```

초안을 읽고 실제 증거와 맞으면 **본인 이슈에 직접 댓글로 남깁니다.** 완료 조건을 확인했다면 In Review(검토 중)로 옮기고 도형준 또는 정해진 검토자에게 확인을 요청합니다. 다른 팀원의 검토와 통합 재현을 마친 뒤 Done(완료)으로 바꿉니다.

진행 상태는 **대기 → 진행 중 → 검토 중 → 완료**라고 생각하면 됩니다. 막혔을 때는 완료로 넘기지 않고 필요한 도움을 기록합니다.

## 매일 작업을 마칠 때 · 3줄 기록

작업한 날에는 본인 이슈 댓글에 아래 세 줄을 남깁니다. 결과가 완성되지 않아도 현재 상황을 남기면 다음 사람이 이어서 도울 수 있습니다.

```text
오늘 한 일: [실제 수행한 일 한 문장]
확인한 결과: [파일·화면·실행 결과 링크 또는 아직 미실행]
다음 할 일 / 필요한 도움: [다음 행동 또는 막힌 단계]
```

작업을 못 하는 날은 가능한 다음 작업 시점을 도형준에게 알려주세요. 자세한 보고서보다 사실과 다음 행동이 보이는 짧은 기록이면 됩니다.

## 플러그인을 쓸 수 없을 때 · 본문 복사로 진행하기

1. 브라우저에서 본인에게 배정된 Linear 이슈를 엽니다.
2. 목표·기한·선행 작업·할 일·완료 조건을 복사합니다.
3. 일반 AI 채팅에 위 ‘질문 2’와 이슈 본문을 함께 붙입니다. “Linear에 직접 연결되어 있지 않으니 붙인 본문만 근거로 도와줘”라고 덧붙입니다.
4. AI가 제안한 결과를 직접 확인하고, 진행 기록과 증거는 본인이 Linear에 옮깁니다.

프로젝트 초대 자체가 안 되었다면 도형준에게 배정할 이슈 본문을 공유해 달라고 요청합니다. API 키·계정 비밀번호·다른 프로젝트 자료를 AI 채팅에 붙일 필요는 없습니다.

## 첫날 완료 확인 · 다섯 개

- [ ] 본인 Linear 계정으로 우리 프로젝트를 열었다. 접근이 막히면 계정 이름과 상황을 도형준에게 알렸다.
- [ ] Linear 읽기 테스트를 했거나, 사용할 수 없어 본문 복사 방법으로 진행하기로 정했다.
- [ ] 도형준에게 실명·희망 역할 B\~E·가능 시간·도움이 필요한 부분을 전달했다.
- [ ] 배정된 이슈 한 개의 목표·마감·선행 작업·완료 조건을 확인했다. 배정 전이면 배정 요청을 남겼다.
- [ ] 작은 산출물과 실제 확인 결과를 남겼거나, 막힌 단계와 필요한 도움을 구체적으로 보고했다.

첫날 모든 작업을 Done으로 만들 필요는 없습니다. 결과물이 완료 조건을 충족한 경우에만 검토를 신청합니다.

## 막혔을 때 이렇게 알려주세요

아래는 **보고 예시**입니다. 실제 본인 상황에 맞게 바꿔 보냅니다.

**프로젝트 접근이 안 되는 경우**

```text
이름: [실명]
막힌 단계: Linear 가입 후 우리 프로젝트 열기
확인한 것: 본인 계정 로그인은 됐지만 프로젝트 목록과 링크가 열리지 않습니다.
화면에 보이는 문구: [실제 문구]
필요한 도움: 제 계정으로 팀 초대가 되었는지 확인 부탁드립니다.
```

**코드 폴더가 없는 경우**

```text
내 이슈: [배정된 이슈 링크]
하려던 일: 기본 화면을 실행해 보려고 했습니다.
막힌 점: Linear 내용은 읽히지만 팀 저장소 주소와 로컬 코드 폴더가 없습니다.
지금 준비한 것: 이슈 완료 조건과 화면에 표시할 항목을 정리했습니다.
필요한 도움: 팀 저장소 초대와 사용할 코드 폴더를 알려주세요.
```

**AI 답변과 실제 결과가 다른 경우**

```text
내 이슈: [배정된 이슈 링크]
입력 또는 실행 순서: [가상 문의나 실행 단계]
기대 결과: [완료 조건에 있는 결과]
실제 결과: [화면 문구·오류 내용·캡처]
시도한 일: [확인하거나 바꾼 것]
필요한 도움: 어느 모듈에서 확인해야 하는지 같이 봐주세요.
현재 상태: 진행 중, 완료 처리하지 않았습니다.
```
