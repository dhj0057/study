팀장: 도형준 · A 기획·공통 처리·전체 통합 담당

처음 30분 안내 · 가입 → AI 연결 → 내 작업 찾기를 연다.

본인 계정으로 프로젝트와 AI 연결을 확인하고, 이름·희망 역할 B\~E·가능 시간을 도형준에게 알린다.

배정받은 T번호 작업 한 개에서 첫 행동 → 결과물 → 확인 방법 → AI 요청문 순서로 진행한다.

작업한 날에는 한 일·실제 증거·다음 할 일을 본인 이슈 댓글에 남긴다. 완료 조건을 확인하면 In Review로 옮겨 검토를 요청한다.

첫날은 가입·연결 확인과 작은 산출물 한 개까지면 된다. 코드는 팀 저장소와 작업 폴더가 준비된 뒤 시작한다.

프로젝트 목표

대학 문의를 접수하고 AI로 분야·긴급도·검토 필요성을 분류한 뒤, FAQ 안내 또는 관리자 검토로 연결한다. 같은 접수번호로 조회·수정·상태 변경·재시도까지 동작하는 Gradio 데모를 완성한다.

현재 상태 · 2026-10-29

기획서와 PM 실행 계획을 작성하고 Linear 실행 체계를 구성하는 단계다. Jev·Gemini의 무료 실제 호출, 코드 구현, 배포와 30건 검증은 아직 완료 사실이 확인되지 않았다. 고정 예시 화면을 실제 AI 동작이나 완료 성과로 보고하지 않는다.

기술과 결정 시한

Python·Gradio·Gemini를 사용한다. Jev는 10/30까지 결제 연결 없는 실제 호출을 검증한 뒤 적용한다. 불가하면 같은 출력 형식의 Gemini 분류로 대체한다. 수업 기술 2가지 이상, 학생 결제 0원·결제 계정 연결 금지, API 키·개인정보 비노출 조건을 지킨다.

제외 범위

학교 로그인과 운영 권한 체계, 실제 학사 조회, 기관에 대한 자동 발송·배정, 문자·메일, 첨부, 음성, 장기 저장, 통계 대시보드, 다중 대화와 별도 검색 시스템은 제외한다.

업무 구성

상위 이슈 5개는 A 기획·통합, B 분류, C FAQ·답변, D 화면·배포, E 검증·발표다. T01\~T21은 주 담당 상위 이슈 아래 배치하고 협업 역할·선행 작업·마감·완료 기준을 명시한다. A는 팀장 도형준으로 확정했으며, B\~E 실명과 전원 가용 시간은 T01에서 확인한다. 다른 프로젝트의 인원을 자동으로 복사 배정하지 않는다.

최종 검증 기준

분야·부서 최초 판단 24/30 이상은 개발 목표이며 실측 결과가 아니다. 검토 필수 18/18과 그중 긴급 6/6 우선 확인, 일반 안내 12건 FAQ 근거 일치, 오류 8종·두 창 조회·상태 변경·동일 번호 재시도를 확인한다. P0·P1 미해결은 0건이어야 한다.

협업

Linear는 이슈·기한·검증·결정 기록, GitHub는 코드·PR, 기존 팀 대화 채널은 빠른 소통에 사용한다. 정해진 역할·작업 보드·검토 절차를 따라 협업하고, 이 프로젝트 범위 안에서 자료와 작업을 관리한다. 문서와 링크는 아래 리소스에 연결한다.
