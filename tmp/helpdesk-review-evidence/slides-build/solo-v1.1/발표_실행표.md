# AI Smart Help Desk 발표 실행표

시연판 `demo-2026-11-25-ui` (`5046d68`) · Kev-4B Q4_K_M과 Gemini · 가상 문의만 사용

시후가 1–8장 발표와 질의응답을 진행한다. 동현은 화면 조작과 영상 전환을 맡고, 형준은 공지·제출, 성윤은 Kev·학습, 민석은 FAQ 설명을 준비해 시후에게 전달한다. [시후 전체 대본·팀원별 공부 가이드 v1.1](https://docs.google.com/document/d/1vInr7RyGnV2-co2HTO32k5tT7RGGbbN0ZH6hl0Vx3d8/edit)

## 시작 전

1. 교실 PC에서 [로컬 시연판](http://127.0.0.1:7860)을 열고 초록색 문의 입력 화면을 확인한다. 앱이 꺼져 있으면 Kev를 시작한 뒤 프로젝트 README의 로컬 실행 순서에 따라 앱을 실행한다.
2. 발표 자료 8장과 영상 재생 파일을 미리 연다. 다른 PC에서 접근할 때는 [리허설 이슈](https://linear.app/dhj00570-helpdesk/issue/NONONO-31)의 최신 공유 주소로 기존 팀 계정에 로그인한다. 호스트가 시연 앱을 실행한 뒤 주소를 확인한다. 발표는 교실 PC를 우선한다.
3. 수업 공지에서 발표·제출 시각, 제출 위치, 파일명 조건을 확인한 뒤 아래 순서를 실제 제한 시간에 맞춘다.

## 시후 발표 순서 · 동현 화면 조작

| 화면 | 할 말과 확인 |
| --- | --- |
| 1~2장 | 대학 문의를 어떻게 접수하고 담당자에게 연결하는지 설명한다. |
| 3~4장 | Kev가 분야·긴급도·검토 여부를 판단하고, Gemini가 적합한 FAQ 번호를 선택한다. 앱이 해당 FAQ 원문을 보여준다. |
| 라이브 또는 5~6장 | 아래 세 가지 문의를 시연한다. 앱이 응답하지 않으면 16초 녹화 또는 두 장의 캡처로 이어간다. |
| 7장 | 가상 개발 문의 30건에서 전체 19/30, 필수 검토 18/18, HIGH 6/6이다. 11건 차이는 분야·긴급도·FAQ 판단에 있다. |
| 8장 | 팀 산출물과 다음 개선점을 설명하고 질문을 받는다. |

## 시연에 넣을 문의

1. “성적 좋으면 장학금 신청서를 내야 하나요, 아니면 그냥 주나요?” → FAQ-S01과 원문을 확인한다.
2. “장학금 신청 마감이 오늘 6시인데 포털 장학 메뉴가 계속 오류 나요.” → 결과 카드의 **우선 확인**을 보여 준다.
3. “제가 낸 휴학 신청이 승인됐나요?” → 관리자 문의함에서 해당 행을 열어 같은 번호와 원문을 확인한다. 검토 중으로 저장하고 답변·메모를 비운 상태로 완료를 눌러 거절 사유를 보여준다. “가상 문의의 확인 절차를 안내했습니다.”를 입력해 완료한 뒤 학생 화면의 같은 번호로 결과를 갱신한다.

앱·모델이 응답하지 않으면 같은 폴더의 `오프라인_시연_재생.html`을 Chrome 또는 Edge로 연다. 필요한 장면은 일시정지해 설명한다. 재생이 불가능하면 슬라이드 5~6장의 같은 접수번호를 대조한다.

## 예상 질문

- **AI가 틀리면 어떻게 되나요?** 근거가 부족하거나 개별 결과를 묻는 경우 사람이 검토한다. 모델 호출 오류에서도 문의 원문과 번호를 저장하며 같은 번호로 재시도할 수 있다.
- **19/30은 무엇인가요?** 개발용 가상 문의에서 분야·부서·긴급도·검토·FAQ 등 모든 기대 항목을 만족한 건수다. 필수 검토와 HIGH 결과는 각각 따로 집계했다.
- **추가 학습 결과가 반영됐나요?** 라이브와 30건 서비스 검증은 고정된 기본 Kev-4B의 결과다. 추가 학습은 RTX 3080에서 가상 문의 100건으로 마쳤다. 별도 가상 문의 32건의 모델 판단에서 전체 일치 14→25건, 긴급 문의 5→7/8, 필수 검토 9→17/18이 나왔다. [학습 검증](https://github.com/dhj0057/ai-smart-helpdesk/blob/799e9cf/docs/validation/2026-11-19-kev-training.md)

전원이 모이면 다른 PC에서 문의 1건을 접수·조회하고, 시후의 전체 발표 시간을 재고, 백업 영상 전환을 한 번 연습한다. 변경하거나 막힌 구간만 다시 확인한다. 발표나 제출 후 접수 상태를 기록한다.
